## 세부기능 계획
### 1. 입력의 시작 부분 검증
1. 입력의 [0], [1]이 `"//"`이거나 [0]이 숫자인지를 검증한다.  
2. 유효하지 않은 입력인 경우 커스텀 에러를 발생시키며 원인 필드를 추가한다.

### 2. 입력 구분자의 유효성 검증
1. `"//"`로 시작하는 경우에만 호출된다.  
2. `[2]`는 구분자로 입력 가능한 문자이며 `[3:4]`는 `"\n"`이어야 한다.

### 3. 계산 항의 구분자와 숫자 유효성 검증
~~1. 계산 항 왼쪽의 구분자 정의가 있다면 지운다.~~  
~~2. 홀수 항이 모두 숫자인지를 검증한다.~~  
~~3. 짝수 항이 모두 params에 포함된 구분자인지 검증한다.~~  
1. 현재 식별된 구분자들로 입력에서의 피연산자들을 분리한다.  
2. 분리된 피연산자가 숫자인지를 판별한다.  
3. 구분자로 분리된 원소들이 모두 숫자가 아닌 경우 에러를 발생시킨다.

### 4. 숫자의 합을 연산 한 뒤 출력
1. 입력받은 구분자로 구분된 숫자들의 합을 연산한다.  
2. 연산한 합을 출력한다.

##### 역할

##### 원인 결과 그래프 생략

#### isValidSep
##### 역할
피연산자들이 적절하게 구분자로 구분되었는지를 검증한다.

##### 원인 결과 그래프 생략

##### 원인 결과 그래프 생략

## 문제의 문제점 분석
### 구분자로 가능한 문자를 제한해야 하는가? 제한한다면 어떤 문자들로 제한해야하는가?
‘구분자’의 `자`는 字, 즉 구분문자(區分文字)이다.  
따라서 여러 문자의 문자열은 구분자가 아니라고 가정한다.

숫자를 구분자로 입력받는다면 계산에서 제외되어야 하며,  
이는 계산기의 동작에 심각한 영향을 준다.  

‘.’을 구분자로 입력받는다면 소수 입력 자체가 불가능해지므로  
소수점 자릿수 증가 시 입력 제한이 무한대가 된다.

#### 예시 입력
‘//1\\n2113’ → 1을 구분자로 입력받아 잘못된 입력  
‘//.\\n1.2’ → 1과 2로 나뉘어 합 3 출력  

#### 정리
계산항에 영향을 주는 숫자와 ‘.’은 구분자로 제외한다.

---

### 기능요구사항과 입출력 요구사항의 모호성
> "입력한 문자열에서 숫자를 추출하여 더하는 계산기를 구현한다."

이 문장에서의 ‘숫자’는 0~9의 문자일 뿐, 수의 개념은 아니다.  
그러므로 ‘수’를 대상으로 해야 계산이 자연스럽다.  

#### 예시
‘1,20,3’ → 숫자만 추출 시 1+3=4  
‘1,0.3,4’ → 숫자만 추출 시 1+4=5  

→ 그러나 실제로는 1+20+3=24, 1+0.3+4=5.3 이 직관적이다.  

#### 결론
문제에서 말하는 ‘숫자’를 ‘수’로 해석해야 하며,  
소수점 계산이 가능하도록 허용해야 한다.  

---

### 종합적인 정리
문제의 계산기는 **양의 수 전체**를 대상으로 동작해야 한다.  
즉 0~9만이 아닌 실수 포함.  
또한 구분자로 ‘0~9’와 ‘.’은 제외한다.

1. 구분자로 들어올 수 없는 문자 목록 추가  
2. 소수점 계산이 가능하도록 로직 수정
